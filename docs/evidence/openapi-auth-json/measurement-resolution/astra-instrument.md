## Initial findings

1. **P1 — controlled interruption discards the current row.** In the initially reviewed `tools/run_auth_resolution.py:198-208`, both `KeyboardInterrupt` and the watchdog immediately send SIGTERM, with SIGKILL after two seconds. The initial Rust harness has no signal/cancellation handler; its only partial-row serialization is after `sample` returns at `auth_resolution.rs:651-659`. SIGTERM therefore loses every in-memory block from the current row, even for the explicitly controlled user-interruption case. The parent watchdog also expires at effectively the same deadline the child checks only between blocks, so it can kill a normally cooperating child before serialization finishes. Preserve partial row evidence by requesting cooperative cancellation, checking it between complete blocks, serializing the unfinished row with a nonpassing error, and draining/persisting that output. Stop timed work at the hard deadline; a bounded flush must not be a permission to collect more measurements. Retain prior validated checkpoints on every exit. Test the interruption/timeout/partial-row paths without running a benchmark.

2. **P1 — the receipt does not bind reviewed builds to the binaries that freeze accepts.** Initial `prepare` copies `TARGET/release/examples/auth_resolution` after Cargo succeeds, but the Cargo command does not set `--target-dir` or otherwise force its output directory to equal `TARGET`. For the two standalone consumer manifests, an unset or mismatched `CARGO_TARGET_DIR` can leave that copied path stale. The extension then records commands/source inputs, but no copied binary hashes or retained preflight-output hashes; `freeze` independently hashes whichever files currently occupy the binary paths. A replacement or stale binary can therefore become the frozen binary without proving it was the built/preflighted artifact. Explicitly set the Cargo output directory (or consume Cargo's actual executable artifact path), bind each copied binary and each readiness record to the extension, and have freeze revalidate that binding, compiler, instrument sources, and successful checks. Also validate the closed consumer manifest against `closed-snapshot.json.consumerManifest` and its pinned lock/client input before blessing the current consumer tree: the snapshot's `files` covers runtime sources, not `consumer/`. The currently retained closed manifest does equal the historical manifest, but the initial preparation code does not enforce that fact.

3. **P1 — a flushed row is not yet a validated checkpoint barrier.** Initial `auth_resolution.rs:652-656` writes and flushes each row, then immediately starts the next row. Initial `invoke` validates only after the entire subprocess has exited. Corrupt row 0 can thus be followed by more measurement before its rejection, contrary to the frozen instruction to persist a validated raw checkpoint after each row. The coordinator identified this before this report. Implement an acknowledged barrier: persist the exact row, validate identity/fixture/schedule/arithmetic, record its checkpoint hash, and acknowledge before allowing the child to start the next row. Reject or abort without acknowledgment on any error. Preserve incomplete rows as evidence while never accepting them as checkpoints. Deterministic fake-child tests should cover good, corrupt, truncated, and interrupted output.

4. **P1 — frozen fixture hashes are not enforced on observed rows.** Initial `validate_row` checks selected source/context fields but neither complete source/context identity nor actual input/response hashes. For example, it permits an arbitrary configuration key and unvalidated operation/schema members; the deterministic synthetic fixture intentionally uses `test.security`. `prepare` writes `fixtures.json`, but the initial row validator never reads it. Input/response hashes in that manifest are reconstructed from the workload table, rather than observed from the retained Rust fixture. This leaves the plan's exact-fixture requirement unverified for measurement records. The coordinator identified this before this report. Emit the actual retained immutable input/response contents or hashes, compare full source/context/input/response identity to the frozen fixture table in both preflight and measured validation, and verify that table's complete expected key set. Use an explicit synthetic fixture dependency in deterministic tests rather than weakening production validation.

5. **P2 — review-file presence is treated as an acceptance gate.** Initial `freeze` requires only that `astra-instrument.md` and `claude-instrument.md` exist. This very report, which rejects readiness, satisfies that gate. Bind explicit independent acceptance decisions to the final instrument/receipt hashes and reject missing, negative, or stale decisions. The same principle applies to the R result acceptance record: the decision must identify both reviews and the exact raw/provenance/summary evidence they accepted. Merely hashing a report with a negative disposition does not make it an acceptance.

6. **P2 — Q drops frozen reporting calculations.** `summarize_q` retains medians, deltas, ceiling and slack, but omits the historical `auth_ratios = Ca/Da` and `allowance_used = (Ca-C0)/ceiling` calculations required by `performance.md` and the synthesized plan's instruction to retain ratios/formulas. Restore these fields for every pair without changing a gate. Add known-value expectations, including numerical failure with invalid controls, baseline spread above 15%, and slack equal to U.
