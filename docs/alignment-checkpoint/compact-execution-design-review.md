# Compact ordinary execution: independent bounded design review

**Proceed with global annotation demand and certified leaf execution, subject to the stronger leaf criterion below.** This is a design gate, not implementation or performance qualification. Source inspected is pinned in `reviewed-source-hashes.json`. No production edits were made.

The authoritative semantic boundary remains pinned spec c1419c9 §5.5: ordinary validity is JSON Schema validity, undefined dependence includes the annotations collected in each alternative, and each instance is evaluated independently. The approved original-engine design and recursive coordinate certificates remain requirements. No default limit or workload expectation changes are needed or authorized by this review.

## R-CE1: zero schema children is not a sufficient leaf certificate

Priority: P1 if implemented with the proposed shortcut. An activated applicator can affect validity while containing zero schema children. Under the existing permissive selected custom meta, `anyOf:[]` and `oneOf:[]` both return F for all six JSON kinds; `allOf:[]` returns S. The independent public probe and its 18 observations are retained here. A certificate based only on whether a selector found an object/boolean child would classify all three alike, then a return after primitives/format/pattern would turn the first two into S. Malformed active applicator operands also must not be silently ignored because no indexed schema child was found.

For the first increment, exclude a node from the leaf path whenever **any active evaluation-applicator or reference keyword is present**, regardless of operand shape, size or child count. This includes all/any/oneOf, not, if/then/else, properties/patternProperties/additionalProperties/propertyNames, items/prefixItems/additionalItems/contains, dependentSchemas/schema dependencies and unevaluated keywords, as applicable to the node's profile. Conservative exclusions of contentSchema, unused definitions and orphan branches are acceptable. Optimize empty containers only after a separate proof. Disabled-vocabulary fields and draft-07 ignored siblings follow the actual Profile; do not inspect raw spelling as a new interpretation authority.

## Why the global two-bit demand is sound

Prepare independent `properties` and `items` demand bits from the complete activated original-node closure. Property demand is on if any known active `unevaluatedProperties` consumer can execute; item demand is analogous. Include all dynamic/recursive candidate targets, child-instance subschemas and every distinct `Plan::at` entry used for actual meta validation. A consumer in a different instance kind can still require its dimension globally: an array's items may contain an object consumer, and an object's property may contain an array consumer.

With neither known consumer nor an API exposing these evaluated-coordinate annotations, outward coordinate sets cannot affect any known validity transition. Unknown content remains an opaque validity effect whose possible contents already include its own internal consumers and references back to addressable schemas. Its outward annotations are unobservable when no known caller consumes them. This argument depends on the **immutable, closed prepared graph** and the current opaque treatment: no late fetching, profile activation, partial external evaluation or inventory expansion may start consuming omitted coordinates without recomputing demand.

This refines the earlier architecture note's conservative advice to retain demand on unknown edges. Retaining both bits is always safe, but is unnecessary for wholly opaque content when every known consumer is absent. If uncertainty prevents proving the known executable closure complete, retain both bits or refuse the unsupported inventory; do not infer no demand from an incomplete walk.

Uncollected is not a proof of empty. Keep demand explicit in Plan (or use an unobserved coordinate variant). With a bit off, skip that dimension in `unknown_schema`, producers/merges, `recursive_cut`, `certify_coordinates`, support discovery and fact commits. Never read an omitted map's default FALSE as a certified absence. Continue validity refinement, cut independence and opaque fallback unchanged. Whenever a bit is on, preserve its complete existing annotation/coherence path, including formula-valued producer support, pending-versus-committed facts, failure gating and exact UTF-16 names.

Local keyword computation remains required without outward maps: `additionalProperties` needs local explicit/pattern selection, legacy additionalItems needs tuple position, and contains needs exact match counts/min/max tests. Merely avoiding `state.properties.insert` is insufficient for the intended allocation reduction: the additionalProperties-only object loop must also avoid unconditional `units(member.name)` and name clones when nothing else needs ownership.

## Smallest safe execution and memo change

Retain inline `State::truth(Formula)` with empty maps, or an equivalent private validity-only variant; empty BTreeMap construction is allocation-free. A new parallel evaluator or public result type is unnecessary. Certify eligible, known-profile, inventory-good leaves during the existing accounted preparation walk using the stronger criterion. Keep the evaluation tick/depth check and original resource `enter` semantics. Execute the same primitive/format/pattern helpers and return without Visit, active-stack storage or persistent State memo for these leaves. No child evaluation means a leaf cannot join an in-place recursion component; an uncertain primitive still uses the existing original-effect identity and typed cause machinery. Do not infer leaf safety merely from a returned constant after arbitrary child execution.

Keep all non-leaf complete-State memoization in this increment. Same-instance reference diamonds require sharing, and complete producer summaries are used as formula-valued support bounds by recursive refinement. Retain original occurrence plus effective scope for active recursion, exact value interning only for effects, and original locations for diagnostics. A leaf has no annotation producers or recursive children, so omitting its empty completed memo cannot erase a producer certificate; raw support inspection also finds no producers there. Avoid broad 'do not memoize concrete results' rules, which would drop useful non-leaf sharing and support proofs.

This is sufficient to target the frozen workloads: the 20k array and late-invalid array repeatedly call an integer/minimum leaf; the 50k object repeatedly calls an integer leaf and has no unevaluated consumer. Their primitive arithmetic remains size-charged; eliminated allocation is empty context copying, leaf Visit/memo retention and unused coordinate ownership. Other reference/depth/diagnostic workloads stay separately open.

## Allocation and control invariants

An empty Vec Context clone and empty BTreeMap State clone request no heap allocation. Preserve a work/cancellation tick but charge zero allocation for those exact operations. Charge the containing map/vector insertion separately when one actually occurs. Do not reduce the existing nonempty name/map/context reservations by analogy; preserve their documented ownership and growth accounting. `enter` with an empty context and no introduced binding can return an empty context without heap allocation; introducing dynamic or recursive bindings still reserves their strings and storage before construction.

An allocator probe should exercise empty versus nonempty Context/State copying directly, plus complete large-job requested allocations and release. Cancellation and real work limits remain checked through leaf loops; cold/cached preparation failures never publish partial demand/leaf certificates. Any fallback or future concrete-to-formula promotion shares the same cumulative ledger. This review does not certify a smaller native stack-frame constant or remove the separate iterative-frame requirement.
