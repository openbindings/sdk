# Independent original-engine contains counter review

Bounded **PASS** for the concrete-count increment at `da39d8b`, 2026-11-03. Exact source identities and original code are retained in `source-hashes.json`/`original`. No production edits. The subsequently started prepared-query cache is a separate review.

The invariant is: `concrete` counts only predicates already proved TRUE; `uncertain[k]` is the exact coherent Boolean formula for exactly `k` additional true predicates among all nonconstant results processed. FALSE contributes neither count nor uncertainty. Adding TRUE changes only the offset; adding a nonconstant formula uses the same mutually exclusive recurrence as before: `next[k] |= old[k] & !p`, `next[k+1] |= old[k] & p`. This does not treat repeated or complementary predicates as independent events. `within` selects exactly those formulas whose offset plus uncertain count falls in the inclusive requested interval. Empty/reversed intervals, zero, and unbounded maximum retain their ordinary meanings. Checked addition refuses count overflow.

The integration changes only that recurrence and range reduction. It still evaluates each `contains` child and records each original item's result formula for 2020-12 annotations. It does not short-circuit at `minContains`, erase nonmatching items, or substitute count validity for item annotations. The existing edition guards, numeric bound parsing, and `unevaluatedItems` application remain unchanged. This follows pinned §5.5's JSON Schema interpretation; it adds no new Undefined criterion or dialect behavior.

Independent verification:

For 200,000 concrete additions the counting allocator observes **zero requested heap bytes**, both before any uncertainty and after one uncertain predicate is retained. This is the counter's allocation observation, not a claim that the entire semantic evaluator is allocation-free.

This result does not authorize a wholesale backend switch or relax any frozen workload/performance gate.
