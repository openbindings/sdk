## Representation and reservation

Fields is 8 bytes. On both native Rust versions, Frame grows from 248 to 256 bytes; the initial four-frame backing changes from 992 to 1,024 bytes. Phase/State/Witness remain 144/64/32 bytes. The actual Wasm32 target compiler reports Frame 128→136 and State 32. The Wasm method uses intentional array-length diagnostics against the actual private source and exact Cargo-fingerprint dependency set; the final compilations have only the two intended layout errors. It is layout evidence, not an additional Wasm runtime or physical-stack qualification.

The 136-byte per-entry preparation charge is acceptable under the existing **scoped SDK reservation estimate** contract. It explicitly charges newly retained non-leaf descriptors as well as replacement leaf entries, before map allocation/publication. It does not purport to certify every allocator/compiler HashMap implementation. Finite actual native allocation measurements at 13 growth boundaries (1 through 3,585 inserted descriptors) stay below the cumulative charge and release all incremental live storage. At 3,585 entries the map requests 278,556 bytes over 12 allocations, peaks 208,912 bytes above the measurement baseline and returns to baseline after drop. No dense table is allocated for an unused 5,000-node supplied inventory. Frame storage continues to reserve its actual type size, so the new word is accounted there too.

Parent measurements separately report +32 requested evaluation bytes for several selected non-leaf jobs and about 272 KiB extra preparation requests for reference5000. These are real preparation/layout costs to retain in later performance assessment, not grounds for claiming an allocation-free optimization.
