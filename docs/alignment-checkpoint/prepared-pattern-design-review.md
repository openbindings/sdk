# Prepared original pattern artifacts: bounded design review

Decision: proceed with retained readings and immutable Simple matchers. Do not eagerly compile every PikeVM under the current reservation schedule. Full once-prepared VM programs remain an open OE-06 increment, as does retirement of the ordinary schema compiler.

Authority is pinned spec c1419c9, §5.5: pattern values and patternProperties names use ECMA-262 Unicode semantics; invalid expressions produce undefined results only where validity depends on them; values are evaluated separately. Prepared artifacts change ownership and repeated work, not these rules.

## Concrete eager-construction regression

The unchanged original-Plan probe accepts empty objects against schemas with 100, 300, 400 and 1,024 distinct non-Simple property patterns (all outcomes Satisfies). Exact schemas, observations, binary identity and timing evidence are in `eager-preparation-hazard.json`. No corresponding property is present, so none requires a VM search. Each eager first build would reserve at least 48 KiB × 32 + 4 KiB = 1,576,960 bytes. Four hundred reserve 630,784,000 bytes, already beyond the unchanged 512 MiB preparation default; 1,024 reserve 1,614,807,040 bytes. The current total-pattern policy admits 1,024 initial compiled forms. This is a concrete reason to stage the change, not a request to enlarge allowances.

## Required representation and failure invariants

- Index retained readings by original arena plus operand node, after profile activation and reachable original-schema discovery. Use original locations for invalid-pattern effect identities even when valid normalized programs are shared. Do not inventory literal data, disabled vocabularies or draft-07 reference siblings.
- Ordinary value-pattern forms keep their existing distinct-form policy. PatternProperties names keep their existing per-name accounting. Deduplicate ownership where policy already deduplicates forms; cumulative preparation reservations must still cover each attempted parse, temporary reading, form clone, Arc and index allocation.
- Simple matching may borrow immutable retained state. VM compilation remains once per reached operand per call in this increment; its Cache remains exclusive to that VM/call. Do not retain a preparation control, instance or mutable search cache in Plan.
- Invalid syntax remains a local Undefined reading; supported-syntax inability remains an inability. VM capacity/size refusal is a terminal Limit when the predicate is reached, never an uncertainty atom. Current eager applicator evaluation does not promise to mask such a terminal beside a decisive branch. Actual cumulative ledger exhaustion remains sticky and aborts preparation.
- Missing prepared inventory is an EvaluatorFailure, not permission for a runtime parse or changed interpretation. Cancellation must be observed before published preparation success and after completed matching, with clean retry and no cached failed attempt.

## Gates for this increment

Exercise retained low-work Simple evaluation, concurrent VM property matching, invalid/unsupported/non-string and decisive branches, equal-text/different-origin versus repeated-reference effect identity, ignored/profile-disabled locations, exact Unicode and non-scalar refusals, owner/snapshot retention, normalized-form dedup versus separately counted names, source/form/depth/total-policy boundaries, preparation and evaluation cancellation at every observed checkpoint, low-cap refusal/retry, and 400/1,024 unused VM operands. Run existing pattern correctness, required evaluator corpus, recursive/coherence controls and custom-meta allocation checks without oracle or default-limit changes.

## Still-open compiler certificate

The existing lexical parser reservations are preserved. Finite earlier allocation controls for PikeVM do not prove the current `256 × form + 32 × NFA allowance + 4096` multiplier for every compiler shape. Before promoting immutable VMs into preparation, audit regex-syntax AST/HIR, repetition/class expansion, Thompson builder scratch/final compaction, failed retries, and retention together. Search cache bounds must cover sparse sets, capture-free slot scratch and epsilon-stack growth, not merely initial allocation or a library memory_usage value that reports vector length. Existing per-call compilation is unchanged by the narrow increment; this review does not close that certificate or claim full OE-06 completion.
