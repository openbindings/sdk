# Owned HIR stage — independent bounded design review

Status: **approved to implement as an inactive private stage**, with the ordering and source conditions below. This does not approve once-prepared VM activation, the complete default construction budget, or an arbitrary Rust build's physical-stack footprint. Production HIR-stage implementation did not exist when these controls were authored. The small Reader ceiling correction is assessed separately below.

## Recommended contract

Use one factory owning the entire exact-form → guarded AST → checked inventory → logical admission → fresh HIR translation sequence. Do not accept a caller-supplied AST/certificate beside a second form. Explicit `TranslatorBuilder::utf8(true)` matches the present ordinary PikeVM parser configuration. Keep default Unicode mode, flags, and line terminator; only the guard's indivisible ASCII-boundary group may disable Unicode locally.

The internal logical ceilings of **64 prospective simultaneous prefix-constructor calls and 256 prospective equality levels** are acceptable for this inactive stage. They are explicit SDK capability choices, not numbers mandated by the specification or a proof of a particular byte floor. They cover the retained/generated prior maxima of 40/88, and the independent controls now exercise 63/64/65 and 255/256/257. A source-depth request cannot raise them. Combined prefix/equality paths still need physical-build evidence before an advertised floor or activation. Refusal remains a typed local construction limit; it cannot become an Undefined pattern effect.

The source Reader must independently cap authored recursion at 32, allowing smaller caller limits. Apply the cap before Reader recursion. The normalized closed grammar admits checked `D + 1`, where D is the **effective clamped authored allowance**: captures/noncaptures and supported terminal positive lookahead each preserve their one source group, while a boundary or empty scalar atom adds at most one fixed group. This does not permit a 33rd authored group. The AST representation ceiling remains a different condition. Synthetic checked-add overflow is a private arithmetic control; a public `usize::MAX` source request is first clamped to 32 and does not itself require arithmetic refusal.

The simplest honest physical contract is checked logical admission plus recorded build/artifact stack evidence. Rust ≥1.88 is build compatibility, not identical frame layout across arbitrary targets, optimization, LTO, custom flags, future compilers, or caller frames. No runtime rustc allowlist is needed. Source-build callers provide adequate stack; maintainers qualify the concrete supported native configurations and shipped Wasm artifacts they advertise. The pinned core §5.5 and §9 prescribe schema meaning and address resource/stack attacks; they do not impose byte-exact portability across arbitrary Rust compiler output. Cargo also gives profile control to the consuming workspace, so a dependency cannot fix that output itself ([Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html)).

The previous 256 KiB / 192 KiB recursive-window / 64 KiB residual proposal is retained as historical target-specific evidence, superseded as a universal source-SDK reading. Do not replace it with an unmeasured new universal floor. Qualify current/minimum Rust, the actually advertised native targets, relevant debug/release/archive-consumer/LTO configurations, and exact linked Wasm plus hosts before making corresponding claims. Custom build responsibility does not waive unchanged default workloads, supported-build failures, or resource accounting.

## Required construction order and ownership

1. Observe the shared control; derive clamped source/normalized limits with checked arithmetic. Run the guard and prepaid AST stage.
2. Consume Parsed into the existing checked streaming inventory. Do not invoke translation while collecting a prospective certificate.
3. Check the non-bypassable prefix/equality limits. Observe cancellation/sticky failure before returning a profile refusal. Inventory arithmetic refusal may occur earlier, particularly on 32-bit targets, and must remain distinct.
4. Charge the checked HIR work and allocation site totals before constructing/translating. Account the small fixed admission/owner-transfer path explicitly from its implemented operations and actual types; do not introduce a guessed stack coefficient or silently charge only the successful path.
5. Translate once with a fresh translator and the same borrowed form/owned AST. Drop translator and AST ownership before the completion check. On cancellation/exhaustion, destroy the produced HIR using prepaid cleanup. On an unexpected backend error, drop it without formatting; retain neither the source-owning diagnostic nor caller control.
6. Return immutable owned HIR. Later NFA retries borrow it; they cannot parse or translate again. No mutable global/cache or attempt escapes. A local representation/profile refusal must not poison a shared attempt; actual enclosing resource exhaustion remains sticky.

The source audit in `translator-error-closure.md` excludes the HIR diagnostic source copy for the locked closed grammar and configuration. Consequently a speculative full-form error-copy reserve is not required for this stage. This is a source certificate, not an inference from zero observed errors. Any grammar, default flag, parser/translator dependency, or relevant source drift must invalidate/review that certificate. The AST stage's separately qualified error-copy allowance remains intact.

## Independent controls and observations

`controls.json` contains **53** pre-implementation controls. The first 47 are preserved in `initial-controls-47.json`; the final set adds six Reader contract cases. The two unchanged `\p{Cs}` source rows are earlier Reader `Unsupported(PropertyEscape)` controls, not HIR-admission positives. The initial mistaken interpretation and actual results are retained. Supported empty-class and lone-surrogate forms independently establish the extra normalized group.

The independent configuration probe exercised **1,184 rows**: 1,142 retained forms, 18 independent forms, and 24 configuration/representation/negative cases. **1,175 translated**, with no translator errors and identical HIR under UTF8 true/false on this guarded scalar domain; nine rows refused earlier. This does not adopt UTF8 false. Six independent configured-program groups (18 existence answers) also match their fixed expectations, including flag restoration, astral ranges, exact anchors, empty language, and nullable repetition.

The prefix boundary witnesses were refined before implementation because the first forms made the independent 32-bit work sum overflow before the intended profile check. Those original forms/results remain in `initial-profile-boundaries.jsonl`. Final forms use empty alternatives to preserve C=63/64/65 with E=3 and fit 32-bit work arithmetic; the original independent recursive oracle, not production inventory, derives their named sites. The equality controls use at most 32 source groups and have E=255/256/257 with C=15. They require explicit generous test funding and are **not default-budget performance claims**. Exact/one-below aggregate budget and cancellation controls use the tiny frozen form instead.

## Small Reader correction

The observed patch introduces `MAX_GROUP_DEPTH=32`, applies `min` inside `pattern::read` before scanning/recursion, shares it with the default Limits value, and documents the ceiling in Rust/TypeScript. This is coherent with the agreed supported capability; it preserves default behavior while closing a caller bypass. The added 10,000-group / unbounded-request case is valuable. The independent copied-source recheck under `reader-hard-ceiling` passes 1,191 rows: all 1,184 previous observations are identical, and all six added contract cases plus an additional 10,000-group request pass. The production Reader correction is approved within this bounded scope. This review does not edit SDK files.

## Final private API refinement

The parent selected `prepare(normalized_form, control)` with fixed normalized ceiling33 and AST ceiling250. This is coherent: lower authored limits have already been enforced by Reader, and the factory cannot receive a mismatched AST. The final synthetic depth-add overflow control tests arithmetic rather than demanding failure for a clamped public request. The parent also elected to reserve a defensive one-form source-copy allowance before HIR translation. This conservative explicit reserve is acceptable despite the source exclusion, provided it is included in cumulative default-job evidence. The proposed fixed64 ownership/admission batch is not approved by this design receipt; implementation review must map it to actual fixed operations and type transfers.
