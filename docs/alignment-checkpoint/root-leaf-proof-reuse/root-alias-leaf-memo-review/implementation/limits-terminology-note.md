# G5 follow-up — evaluation allowance terminology

Recommend a separate greenfield naming cleanup after this frozen performance experiment. This is not a runtime-correctness blocker and authorizes no API change by this review.

`program_bytes` is now a misleading phase/owner name: it supplies Graph's per-value-call SDK reservation allowance, including memo/copy/scratch/search-cache and optional diagnostic work. It does not bound the immutable prepared pattern programs, which have their separate representation limit. Its existing documentation correctly disclaims total process memory but still says “program growth.”

`evaluation_steps` is less misleading, but `work units` is the accurate unit: Graph debits explicit SDK work sites, variable-size scans and nontrivial proof traversal; it is not a stable count of schema steps or control callbacks. The latest free terminal algebra makes that distinction especially useful.

A clear pair is `evaluation_sdk_work_units` / `evaluation_sdk_reservation_bytes` (TypeScript `evaluationSdkWorkUnits` / `evaluationSdkReservationBytes`). Keep the current optional/no-additional-cap semantics and numeric defaults. Document that one evaluate/explain call shares remaining allowance across the verdict and diagnostic passes; selected-meta evaluation also debits its enclosing preparation Attempt. Reservation units are cumulative SDK charges, not exact allocator requests, peak live bytes, immutable program footprint or a process ceiling. Custom evaluator callbacks and dependency work do not acquire a new universal accounting promise.

If adopted, change Rust/serde/Wasm/TypeScript/options/docs/map bindings together, explicitly reject retired keys under the ordinary unknown-option policy, and update only configuration spellings in tests/measurement adapters. Preserve input jobs, limit values, outcome classifications and historical receipts. Do not combine this nomenclature cleanup with a quota, accounting-site or semantic change. The related sentence in docs/schema-evaluators.md describing the migration's single-build pattern compiler as still in progress also merits a current-status correction; whole resource/performance qualification remains a separate open claim.
