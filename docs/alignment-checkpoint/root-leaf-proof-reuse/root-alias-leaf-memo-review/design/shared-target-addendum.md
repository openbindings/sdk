# Shared-leaf descriptor filter — design addendum

**GO for this refinement before implementing root alias-leaf memo reuse.** It replaces the global `queries.len() > 1` opportunity filter in the preceding design. All other root-occurrence, post-alias, Visit/context, independent-State, accounting, witness and lifetime conditions remain. This is a static review at f62f477; no SDK edits or CPU probes were performed.

Two spare bits in the existing u64 Fields are enough to saturate direct incoming query count at two. After the activated preparation traversal is complete, visit every PreparedQueries entry. For an Ok target, get an already-present descriptor and update it only when `is_leaf()` is true: first entry sets seen, second and subsequent entries set shared. Do not insert descriptors, clone targets/keys, create a count map, or infer a leaf certificate from query success. Count original query entries, not distinct query Arcs, URI spellings or target resources: the existing preparation cache may intentionally share the same Arc across several real reference occurrences.

Keep both bits disjoint from all keyword, Original and leaf bits. `is_shared_leaf()` must still require the ordinary certified-leaf condition, so an Original fallback cannot gain eligibility. Extra flags must not change may_read, logical/object/array phase selection, profile interpretation or any existing leaf result. The Fields and Frame layouts stay unchanged; only the already-approved Run root ID adds a scalar.

Charge/check each finite pass iteration, including Err queries, absent descriptors and non-leaf targets. Mutating a scalar after the check needs no new storage reservation. Preserve a shared completion check after the pass before a prepared Plan escapes; if an existing enclosing completion path supplies it, reuse that path. A work/cancellation failure drops the locally assembled result rather than publishing partial flags. The pass is order-independent because the two-state update is monotone and saturating. Do not turn HashMap iteration order into a semantic property or require identical node visitation order across runs.

The precise fact is **at least two inventoried direct successful query edges target this certified leaf**. It is neither necessary nor sufficient for actual repeated root execution: indirect singleton aliases and dynamic selections can revisit an unmarked leaf; two marked incoming edges may execute only at different child instances. Those are optimization misses/false-positive opportunities, not refusals or changed semantics. The root-instance guard still rejects child/name instances, and final post-alias node/context selection still controls lookup. Do not mark dynamic-selected alternative targets by speculation.

This is a worthwhile reduction in accidental one-use memo work: a linear chain has only one incoming query to its terminal leaf, and an ordinary single external wrapper does too. Direct duplicate references in the unchanged 5000 job qualify. It adds a linear preparation pass and two scalar flags, avoiding a runtime recency structure, a new table or wider retained records. The scope remains small. Measure compile cost and the two-reference/different-instance negative as well as the canonical root-reuse job; no speed or G6 claim follows from the cleaner representation.

`shared-target-controls.json` adds eight frozen groups. Keep earlier RL-01 and RL-04 through RL-13 controls with the new eligibility predicate; RL-02 and RL-03's coarse query-count expectations are superseded by ST-02/ST-03 below. The original control file remains preserved as design history.
