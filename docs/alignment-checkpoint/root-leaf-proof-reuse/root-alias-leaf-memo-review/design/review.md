# Root-instance alias-leaf reuse — bounded design review

**Conditional GO for the proposed narrow experiment using the existing Run memo.** Source reviewed at `f62f47757ba6682bea316492056428a665a7bea4`. No SDK edits, builds, tests or performance probes were made. The existing original-node engine, preparation certificates and alias resolution remain authoritative.

## Safe seam and key

Leave the first/direct certified-leaf exit untouched. Only after ordinary alias normalization has completed, pure cycles have been handled, and the final node is independently certified as a leaf, consider reuse. Require both `backend::ref_id(value) == root_instance` and `plan.queries.len() > 1`. Set `root_instance` once from the actual public evaluation value's view when constructing each Run. Do not assume its ID is zero: retained subtrees can keep a nonzero arena position. Do not substitute `Values::intern` or semantic equality for this occurrence guard.

The existing `Visit` must use the final original node, that instance occurrence, and the full entered effective Context. Alias already enters every selected node, so do not enter the target again or shorten its walk. Dynamic/recursive dispatch and ambiguous bindings finish before lookup. Content-based Context equality, not Arc address or only target node, remains necessary for effect/cause identity. Even a reference-free leaf may contain an undefined/unsupported predicate whose identity includes scope.

The instance ID is sufficient here because one Run receives one live immutable value arena. All instance requests retain the root or select array elements, object values or member-name tokens from it. `propertyNames` passes the original member-name token; those tokens have their own arena IDs and cannot equal the enclosing object's root ID. Schema operands are not substituted as instance requests. Separate values, meta-schema evaluations, Explain passes and concurrent calls construct separate Runs. This invariant must remain explicit; a later change introducing foreign instance arenas would require revisiting the key.

## Query-count premise

The `>1` guard is a sound conservative opportunity filter. Original child positions form a finite tree, with distinct authored occurrences. Same-instance logical traversal cannot reach one identical leaf occurrence twice without a reference edge providing a second route. With only one prepared reference query, following it to a leaf terminates that route; following it back to an ancestor creates a cycle, not a second completed leaf route. Child-instance iteration does not revisit the exact root occurrence. Pure alias cycles are handled before this seam.

However, this is **not** a guarantee of beneficial reuse. A two-edge linear chain or another prepared but unused query can pass the guard and insert a one-use leaf State. Count actual Plan queries, including the SDK's external-root reference wrapper, rather than authored `$ref` strings. An ordinary supplied scalar target commonly has one wrapper query and stays on the no-memo path; a supplied alias chain may have more than one. These false-positive costs need a small negative measurement/control, not a stronger architecture or a semantic assumption.

## Publication and accounting

Use the existing memo only. Before key lookup perform the existing context/key work and retain the entered Context in the Visit. A hit returns `known.copied(&mut graph)` just like ordinary memo reuse. A miss evaluates the same `begin` leaf body. Publish only a successful `Beginning::Ready(state)` satisfying the existing cut-independence predicate. Never cache Limit, Cancelled, other errors, a provisional cut, or a manufactured fallback result. No new leaf truth shortcut or child suppression is authorized.

Before publication repeat the existing completion-side context/key work, then perform `State::copied`, the existing memo insertion reservation and insertion in the same failure-safe order as completed applications. Do not silently remove the State copy allowance merely because the leaf annotation maps happen to be empty. Ordinary no-query/single-query and direct-leaf paths should not pay the new key/copy/insertion costs. `HashMap::new` already exists in Run and allocates no backing until used; add only the root ID scalar, no second map or Plan metadata.

Completed leaves have no annotation producers under the existing preparation certificate. They can nevertheless carry FALSE with a witness, Undefined or Inability formulas and an attached cause. Those completed States are valid reusable proofs at the same node/instance/context. The Graph and atom owners remain alive throughout the Run; no formula or witness escapes into Plan. Newly admitted complete memo entries may trigger the existing support-cache invalidation and another refinement round. The independent publication guard and finite unique keys preserve the existing monotone progress argument; do not bypass that machinery or infer absence from a missing map.

Existing entry, alias, scope and returned-child checks still run on every visit. Hits intentionally remove repeated predicate work and dependency calls after that proof is known, just as current non-leaf memo hits do. `State::copied` and context work continue to observe ordinary cancellation and the shared preparation Attempt. No callback-count equality is promised. A failed publication or hit-copy must propagate normally; it must not become a successful proof. Within-run completion is not a new cross-call cache: errors drop that Run and healthy retries start fresh.

## Witnesses, costs and alternatives

The cached failure seed points to the same original target node and exact root occurrence, so existing parent witness selection/guarding remains correct. Outcome and diagnostic passes have separate Runs and fixed witness mode; an Outcome State must not be reused in Explain. Source lifetime remains Plan-owned. Exact non-scalar locations, external source ownership and concurrent reuse need explicit controls.

This should remove repeated primitive/format/pattern interpretation in the reference-5000 job, but alias walks, query lookup, scope work, memo hashing and bounded State copying remain. It cannot be assumed to close the gap to the old compiler. A miss adds the existing insertion/copy cost; each hit still spends the conservative State-copy allowance. Many distinct root leaves or contexts can therefore cost more than before, while the configured generic memo/work bounds still apply. Root-only admission is essential to avoid the previously observed per-array-item retention problem.

Reusing the current memo is simpler than a Boolean-only result cache (which would require separate cause/witness rules), a new Plan cache (wrong lifetime/control boundary), or broad leaf memoization (unwanted per-item retention). Passing the root ID through every request is another representation option, but one Run scalar is a reasonable minimal change. Do not broaden this experiment to optimize empty Contexts or generic copy charges.

`controls.json` freezes 13 groups for positive reuse, no-opportunity paths, filter false positives, nonzero root IDs/member names, large child workloads, scope/effects/cuts, local errors, exact witnesses, publication cancellation, scoped budgets and measured selection. Record actual Run layout on qualified targets. Implementation approval is bounded to this seam; retention requires these controls and matched observations/measurements. No default change, semantic-oracle adjustment or G6 acceptance is approved.
