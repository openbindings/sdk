# Metadata source-operation audit

Accepted for the private inactive inventory at `final-source-hashes.json`. The metric is the documented named source operations plus target-word transfers. It does not count CPU instructions, allocator internals, arbitrary caller callback work, physical stack bytes or elapsed time. A checked word arithmetic operation is a bounded scalar primitive; compiler-generated temporary/ABI spills are not a second source-level algorithm.

The input-dependent traversal has exactly one dispatch per AST node and one acceptance per child edge. Each `Frame::next` accesses one existing child, and no node/accept/finish helper contains an input-dependent loop. Class handling reads a slice length and at most one item's endpoints. The final phase schedule has explicitly fixed loops of21 and7 elements. The only other traversal is geometric backing relocation, charged by initialized frame length. No HIR smart constructor, class sorting, pattern matching or UTF-8 range expansion occurs in this stage.

Entry/root accounting originally used64. That was insufficiently attributed once initialization and ownership return were included; the corrected precharge is checked `3*words(Summary) + 2*words(Subtree) + 32`. It covers initialization, returned payload/caller extraction, completed-root extraction/field transfer, and finite cursors/control/vector headers before they occur. It is142 on the independently measured native layout. The later1024 charge covers final site-array/sum construction and Inventoried publication, not earlier root-return work.

The96 node batch covers fixed variant classification, a checked node increment, Subtree/default fold construction or a bounded leaf inspection, and scalar child cursor setup. A wide class does not scale this batch because its endpoints/shape were already guarded by the AST stage. Frame pushing is separately charged by actual target word width.

The128 acceptance batch no longer merges21 additive counters. Its non-unary path has only3 subtree lineage additions,3 width/height joins and one bounded root-kind branch. The concat branch accounts for lexical AST-literal adjacency and at most the one surviving Shape; the alternate branch has fixed frontier/range/eligibility and first-child facts. Unary acceptance has fixed group/repetition bounds and zero/exact-one collapse logic. Child/Shape transfers are fixed-size. Their source-operation and word-transfer ceilings fit this batch; there is no hidden child/member loop.

The32 unary finish transfers the completed Subtree and performs fixed dispatch; frame pop/ownership is already prepaid. Concat128 includes5 local totals updates,3 checked result extractions,9 direct arithmetic operators,2 fixed growth helpers, collapse tests/field transfers and the returned Subtree. Alternate512 conservatively covers all source branches (including mutually exclusive ones):17 totals updates,20 checked result extractions,58 direct arithmetic operators,7 fixed growth calls,2 fixed polynomial helpers, fixed comparisons/field transfers and the returned Subtree. The helpers only perform checked scalar arithmetic; `sort` computes a polynomial and does not run a sort. The bound is tied to these current bodies, not permission to add a future loop under the same charge.

Final1024 covers the21 work and7 allocation formulas, target-width conversion, checked sums, fixed array movement, optional failure classification, and final owned publication. All relevant algebra uses Amount/checked arithmetic or checked sums. The two arrays have constant cardinality; no shape width appears as a loop here. Overflow is refusal, never saturation into success.

Frame storage precharges checked `3*words(Frame)` for push/pop/completion and eventual scalar cleanup; backing growth separately prepays the initialized-word relocation. Full requested new capacity times actual Frame size is reserved before reserve_exact. Capacity doubling, bytes, relocation and ownership products are checked, and byte extents aboveisize::MAX refuse. The subtraction passed to reserve_exact is safe because this branch runs only when len==capacity and the new capacity is max(4,2*old). Frames contain no allocation-owning child fields or control. The earlier capacity need not be subtracted from the cumulative reservation.

Failure precedence is preserved: arithmetic helpers first observe the existing control refusal/cancellation; allocation overflow marks the enclosing allocation ledger sticky; work overflow exhausts the work ledger. Final post-check precedes publication. Owned AST cleanup remains prepaid by its construction stage, including cancellation/refusal, and no per-attempt control escapes.
